本文档是写作任何供 agent 消费的文档的参考——一个 skill、一份 `AGENTS.md` / `CLAUDE.md`、或一份通过指针触达的文档。包装形式不同，写法相同：让每一者都可预期的是同一组杠杆——agent 每次运行走同样的_过程_，而不是产出同样的结果。

当你要写的文档是一个 skill 时，阅读 [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md)，了解 frontmatter、调用方式选择和路由 skill（router skill）。

## 上下文指针（Context pointers）

**上下文指针**是存在于 agent 上下文中的一个引用：它点名某份上下文之外的材料，并编码了触达它的条件。skill 的 description 是一个；`AGENTS.md` 里点名某份文档的一行也是同一个东西。决定 agent 何时触达材料、触达得多可靠的是指针的_措辞_，而不是指针的目标。一份必须读到的材料挂在一个措辞软弱的指针后面，就是一个波动 bug（variance bug）：先磨利措辞，只有磨利无效时才把材料内联进来。

一个指针做两件工作——说明材料是什么，并列出应当触发触达的**分支（branch）**（分支是文档处理的一个独立场景，不同运行会走文档的不同路径）。常驻指针的每一个词在每一轮对话都要付费，所以它比正文更值得狠剪：

- **引导词（leading word）放最前面**——指针的触发工作正是在这里完成的。
- **一个分支一个触发词。** 给同一个分支换名的同义词等于把一个分支写了两遍；合并它们，只保留真正不同的分支。
- **删掉正文已经承载的身份信息。**

## 两种负载

你添加的每一份文档和指针，花的是两种预算之一：

- **上下文负载（Context load）**——常驻材料对 agent 上下文窗口的占用：`AGENTS.md` 里的一行、skill 的 description，任何每轮都待在上下文里的东西，无论是否触发都在消耗 token 和注意力。
- **认知负载（Cognitive load）**——对人的占用：存在哪些文档、什么时候该翻哪一份。人就是那个索引。这不是要最小化的成本——它是人类能动性的价格；在人类判断重要的地方花它，在不重要的地方去掉它。

只能通过指针触达的材料，以指针自身一行的代价换掉了上下文负载；完全没有指针的材料则全部压在认知负载上。

## 信息层级

一份文档由两种内容构成——**步骤（steps）**（agent 按序执行的动作）和**参考（reference）**（按需查阅的定义、规则、事实）——两者可以自由混合：全是步骤（一份菜谱）、全是参考（一次评审的规则集、本 skill）、或两者皆有。核心决策是每一块内容放在**信息层级（information hierarchy）**的哪一级——这是按 agent 对材料的急需程度排序的梯子：

1. **文件内步骤（In-file step）**——主层级：agent 要做的事，按顺序。
2. **文件内参考（In-file reference）**——按需查阅。一个正当的平级集合很常见（一次评审的所有规则在同一级）——这是正常的布局，不是坏味道。
3. **披露式参考（Disclosed reference）**——推到独立文件里，通过上下文指针触达，只在指针触发时加载。范围从同目录下的兄弟文件，一直到放在任何地方、任何文档都能指向的完全外部参考。

推下去的太少，顶层就臃肿；推下去的太多，你就把 agent 真正需要的材料藏了起来。这个张力就是全部决策。

**渐进披露（Progressive disclosure）** 是沿梯子向下的动作——移出主文件、藏到指针后面——让顶层保持可读。它主要不是 token 优化：它是保护层级的方式。分支是最干净的披露检验：每个分支都需要的内联，只有部分分支触达的推到指针后面。当一份文档有步骤时，本该披露的文件内参考会把步骤埋掉，让 agent 对步骤的注意变成抛硬币——这是波动杠杆，不只是可读性问题。

**共置（Co-location）** 是文件内的配套杠杆：梯子决定一块内容_放多深_，共置决定放定之后_旁边是谁_。把一个概念的定义、规则和注意事项放在同一个标题下，而不是散落各处，读到其中一部分时它的邻居会一起被带上。检验标准：文档读起来应该像专门为这个 agent 写的文档——归组的材料读起来是这样，散落的不是。（共置不同于重复：重复是同一个意思出现在两个地方；散落是一个意思碎在很多地方。）

**蔓延（Sprawl）** 是这里的失败模式：文档就是太长了，哪怕每一行都活着且唯一。注意力在冗余上摊薄，每多一行就多一行要保持相关的东西。解药是梯子：把参考披露到指针后面，按分支或按顺序拆分，让每条路径只携带自己需要的东西。

## 步骤与完成标准

每个步骤以一个**完成标准（completion criterion）**收尾——告诉 agent 工作已完成的条件。两个性质让它成为杠杆：

- **清晰度（Clarity）**——agent 能否分辨完成与未完成？模糊的边界（"达成了理解"）会招致**过早完成（premature completion）**：在真正完成之前结束步骤，注意力滑向_完成这件事本身_。前方可见的步骤——**后完成步骤（post-completion steps）**——提供拉力；标准的清晰度是阻力。按序防御：**先磨利边界**（局部且便宜）；只有当边界本质上就是模糊的_且_你观察到了抢跑，才通过拆分序列把后续步骤藏起来——而隐藏只有跨越真实的上下文边界才有效（一次交接或一次 subagent 派遣；内联调用会把后续步骤留在上下文里，什么都清不掉）。
- **要求度（Demand）**——它要求多少。"每个修改过的模型都有交代"会逼出彻底的工作，"产出一个变更清单"不会。要求度驱动**跑腿量（legwork）**——agent 在工作内部的挖掘，潜藏在措辞里而不是写成独立步骤——而且它不受步骤约束："每条规则都应用"约束一整个平铺的参考集合，正如"每一步都完成"约束一个序列——这正是纯参考文档仍能携带彻底性标准的方式。

最强的完成标准既可检查又要求穷尽。

## 何时拆分

把一份文档拆成两份要花掉两种负载之一，所以只在划得来时才拆：

- **按顺序拆分（By sequence）**——当后完成步骤会诱使 agent 抢跑眼前这一步时，把一段步骤序列拆开。让后续步骤不可见，能逼出对当前任务更多的跑腿量。警惕反向操作：合并序列会把每一步的后续步骤暴露给后面的内容，招致过早完成。
- **按调用拆分（By invocation）**——skill 专属：见 [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md)。

## 引导词（Leading words）

**引导词**是一个已经活在模型预训练里的紧凑概念，agent 运行文档时用它来思考（_lesson_、_fog of war_、_tracer bullets_）。它永远以 token 形式重复出现，从不展开成句子；它积累出一个分布式定义，用最少的 token 锚定一整片行为区域——靠的是征用模型已经持有的先验。自造词也行，只要你定义得清楚，但生造的词征用不到任何先验——你用定义 token 支付现成词免费给你的东西；先找现成的词。

它锚定两次。在正文里，锚定_执行_：agent 每次遇到这个词都取同样的行为；在平铺的参考里，它把注意力聚焦到一类要找的东西上。在指针里，锚定_调用_：当同一个词同时活在你的 prompt、你的文档和你的代码库里，agent 会把这套共享语言和材料联系起来，触达得更可靠。

主动寻找用引导词重构的机会。一个三元组在三个地方各自展开拼写、一个指针用一整个句子比划一个概念——每一段都是在请求折叠成单个 token 的文字：

- "fast, deterministic, low-overhead" → _tight_（一个 _tight_ loop）。
- "a loop you believe in" → _red_——一个模糊的门变成一个二元的可观测状态（这个 loop 在这个 bug 上变 _red_，或者没有）。

你赢两次：token 更少，且给了 agent 一个更锋利的挂钩来挂它的思考。假定每份文档都带着可以被引导词淘汰的重述——去找出来。

**否定（Negation）** 是这个杠杆旁边的失败模式：用禁令来引导会把被禁止的行为拖进上下文，让它变得_更_可得，而不是更不可得。_不要想大象_，大象就是全部；否定是一个弱修饰符，会被强激活的概念碾过去，所以禁令读起来有一半像让你去做那件事的指令。给出**正面**指令——陈述目标行为（"写一行注释"），让被禁行为根本不被说出。禁令只有作为无法用正面表述的硬护栏时才配存在；即便如此，也要和正面目标配对，让注意力落在该做什么上。

## 修剪

- 让每个意思只存在于**单一事实来源（single source of truth）**：一个权威位置，改行为就是改一处。**重复（Duplication）**——同一个意思出现在多个地方——花维护成本也花 token，还会把一个意思在层级上的显要程度抬过它的真实排位。（它是引导词意外的反面：引导词故意重复 token，从不重复意思。）
- **环境（environment）** 也是事实来源——`package.json` scripts、配置文件、目录布局、`--help` 输出——复述环境的文档是**缓存（cache）**：一份查询结果的拷贝，只有查询昂贵时才配得上它的负载。只缓存 agent 自己查不到的东西：不成文的约定、某个选择背后的理由、任何配置文件都不会招供的坑。一个文件、一条命令就能查到的，留给环境——在那里它们不会过期。
- 逐行检查**相关性（relevance）**：这行还与文档的职责相关吗？一行失去相关性，要么因为它从未与任务相关（纯粹的铺陈，或一个本该披露出去的分支），要么因为它描述的行为或世界已经变化而过期。更短的文档更容易保持相关。没有修剪纪律，默认命运是**沉积（sediment）**：过期层沉淀下来——因为加东西感觉安全、删东西感觉危险——直到你必须钻透它们才能找到还活着的内容。
- 逐句猎杀**空操作（no-op）**：一条模型默认就会遵守的指令，花了负载却什么都没说。检验标准——相对默认行为，它改变行为吗？——是相对于模型的，不是相对于读者的：两个人对一个 no-op 意见不合，分歧在于默认行为，解决办法是运行这份文档，而不是辩论。当一句话通不过检验，删掉整句，而不是从句子里删词。这个检验也给引导词打分：一个弱到打不过默认行为的词（agent 本来就挺彻底时写 _be thorough_）就是 no-op，修法是换个更强的词（_relentless_），不是换技术。
