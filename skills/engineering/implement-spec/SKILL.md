# 实现整份规格说明

实验版：衍生自上游 `in-progress/implement-spec`，尚未纳入上游正式插件。

用户提供一份 **spec（规格说明）**，以及说明如何实现它的一组 **tickets（工单）**。目标是在一个汇总分支上完成整份 spec，并形成一个可评审的 PR。只实现一块工作时，由用户选用 `/tuanzii:implement`。

工单是一张带阻塞关系的**任务图**。**frontier（就绪集合）**只包含所有前置工单都已实现、集成到汇总状态并通过相关检查的工单；按就绪集合调度，不把工单编号当作执行顺序。

## 协作方式

- **实现 agent**：每个工单在独立 worktree 和分支中实现，尽可能在后台并行运行；互相依赖或争用同一资源的工作按顺序执行。
- **合并 agent**：逐个将已完成工单合入汇总分支。同一个汇总分支同时只允许一个写入者；探索、实现、合并与评审 agent 共用宿主的并发配额。
- **上下文指针**：通过 spec、工单、调研笔记和提交的路径或链接沟通，避免重复整段已有材料。实现 agent 返回工单标识、提交、验证结果和未决问题。

开始前读取项目的 agent 指令，确认已有 Git/PR 授权和宿主工具。遵守本次会话已给出的授权，不重复询问。项目若对建分支、提交、推送或发布 PR 有额外要求，按其要求执行；没有发布授权时，先完成已获授权的本地实现、检查与 PR 文案，再就尚缺授权的具体操作询问。调用此 skill 不代表可以覆盖用户的未提交修改。

若当前授权不包含 Git 写操作，使用**本地模式**：在普通临时副本中隔离实现，用文件差异或补丁串行集成到本任务的本地汇总目录，不创建分支、提交或 PR。只复制完成任务需要的源码与配置，沿用项目对依赖和环境的约定；用初始快照区分本次改动与用户已有改动。下文的“分支/合入/提交”在本地模式下对应“汇总目录/应用补丁/文件差异”，前置工单以已集成且检查通过为准。若用户原目录在期间被编辑，先核对差异再回填本次补丁。这样可在不扩大授权的情况下交付本地实现、验证结果和待发布 PR 文案。

## 步骤

1. **核对输入。** 阅读 spec 和工单，明确每张工单的验收条件、阻塞边和代码范围。检查缺失引用与依赖环。如果只有 spec 而没有工单，先提取可核对的任务图；确需拆票时建议用户运行 `/tuanzii:to-tickets`，不要自动调用这个仅限用户触发的 skill。完成标准：任务图可调度，未决信息及其影响已明确。

2. **按需探索。** 可派探索 agent 查阅相关代码或外部一手资料。笔记保存到所有后续 agent 都能访问的临时目录，工单引用其路径。完成标准：需要探索的工单能凭这些材料开始实现；不需要探索则跳过。

3. **准备汇总位置。** 在已获授权的范围内创建或复用本任务的汇总分支，并准备 draft PR。PR 说明关联 spec 和工单，只有完整实现的范围才使用关闭 issue 的语法。完成标准：汇总分支与基点（本地模式为汇总目录与初始快照）可追溯；PR 已创建，或待发布的标题、正文及所缺条件已记录。

4. **调度就绪工单。** 为 frontier 中互不阻塞的工单启动实现 agent，各自从当前已验证的汇总分支建立独立 worktree。提供 spec、工单、探索笔记、项目约束及验收标准；可用时加载 `tuanzii:tdd`。完成标准：每张就绪工单都有明确负责人、工作目录和交付条件。

5. **串行合入。** 实现 agent 完成后，由合并 agent 核对提交和验证证据，将其合入汇总分支并运行受影响的检查。保留最后通过检查的汇总基点。合入后出现冲突或检查失败时，暂停向该汇总位置继续集成，修复并重新通过检查后再恢复；独立实现可从最后已验证的基点继续，回收时核对后来合入的变化。不能把“agent 已返回”当作工单完成。完成标准：工单实现已合入且相关检查通过，才解除它的阻塞边。

6. **刷新 frontier。** 每合入一张工单就重新计算就绪集合，并在宿主并发容量内启动新工作。失败工单保留失败原因与现场，依赖它的工单继续阻塞；独立工单可以推进。若没有就绪或运行中的工单而仍有未完成项，指出剩余阻塞原因，不宣称整份 spec 完成。

7. **整体验证和评审。** 所有工单合入后，核对整份 spec 的验收条件，运行项目要求的集成检查，并加载 `tuanzii:code-review` 评审汇总分支相对原基点的全部改动。本地模式没有提交时，生成相对初始快照的完整文件差异，交由评审 agent 按规范符合度与 spec 符合度两条轴评审，不用未变化的 `HEAD` 冒充本次实现。用一个实现 agent 修复评审发现，合入后复跑受影响检查。完成标准：最终分支通过必需检查，评审问题已解决或明确记录为未完成项。

8. **交付与清理。** 在已获授权且满足验收的情况下，将 PR 标为可评审；汇报实现范围、验证证据及限制。仅清理本任务创建、内容已合入且没有未保存工作的 worktree 或普通临时副本，保留失败现场和用户目录。PR 交付不包含自动合并到默认分支。完成标准：交付状态与实际验证一致，本任务临时工作区的保留或清理情况可追溯。
